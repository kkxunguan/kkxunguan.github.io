对GPIO的理解

  • GPIO 电路是简单的物理电路，用来把外部电平转换为寄存器中的 0/1，或者把寄存器里的 0/1 输出为电平。
  • GPIO 本身不做任何逻辑运算，只负责输入/输出数字信号。
  • 逻辑运算（如 1+1、判断等）全部由 CPU 的 ALU 完成。
  • 程序代码存放在 Flash 里，CPU 执行这些代码时，会按指令去读取或写入 GPIO 寄存器。
  • 所以 GPIO 只是一个接口，CPU 才是做运算和决策的核心。

网络学习有感

  1. 网络学习缺乏即时成就感
    学半天只是为了让一个包能成功发出去，不像编程那样能快速产生成果。

  2. 名词极多但本质简单
    虽然实际应用充满各种复杂概念（VPN、网关、SNMP、DHCP、DNS、NAT 等），
    但底层其实都只是“发包—处理—收包”这一条主线。

  3. 企业网络复杂到超出想象
    像奇安信 VPN 这样的系统为了适应各种企业环境，会开发大量模块。
    但真正日常会用到的功能，往往不超过 10%。

  4. OSI 七层模型只是加工流水线
    所有网络设备和协议，本质就是对数据包进行：
    封装、解封、转发、过滤、加密、解密、认证、打标签 等操作。
    每个概念都是这一套加工流程的不同“工序”。

  5. 网络系统的复杂度远超过一般嵌入式
    嵌入式偏向硬件控制，但网络涉及协议、拓扑、安全、路由、加密、策略等大量系统级知识，整体复杂度更高。

  6. 网络知识碎、杂、累
    名词多、层级多、场景多，不仅难记，还容易记完忘，耗费精力巨大。

  7. 网络工作更像“维护”而不是“创造”
    常态稳定没人关注，一出问题就是高压：

    • 正常 → 没人夸
    • 出事 → 全网骂
      很难获得成就感。

  8. 与自身思维方式不匹配
    网络偏抽象、繁琐、规则多，更适合喜欢体系、规范、排错的人；
    而我更偏向逻辑清晰、有可见成果的方向，自然会觉得无趣。

文字类修仙游戏开发有感

1. 旧时代的 PHP WAP 游戏 = 再怎么重构都没有意义

那种 WAP 游戏的代码：

  • 基于 2005–2012 年的手机环境
  • 大量 inline PHP、散乱逻辑
  • 没有 MVC、没有前后端分离
  • 功能堆叠式开发
  • 维护者随手写，完全不考虑未来

你重构它 = 白费力气。

这和你现在的技术时代已经完全不一样。

2. 你研究的所有“文字/MUD 源码”都很老旧，也属于死路

  • MUD 源码最活跃的时代是 1990–2005
  • 大部分代码是 C、LPC、Perl、PHP
  • 逻辑老旧、结构混乱
  • 缺乏现代 UI/UX
  • 不是面向今天的用户的

你拿这些代码当教材，会觉得：

  • 旧
  • 乱
  • 不符合时代
  • 不想深究
  • 带来挫败感

这不是你的问题，是时代问题。

3. 你尝试重构，但不自觉地往现代 UI 靠拢 → 这是对的

  • 你天然倾向“现代化游戏风格”
  • 你不满足于纯文字
  • 你想做更贴近现在用户的东西
  • 文字 MUD 给不了你任何成就感

这不是迷失，而是进化。

4. 真正的问题：你想做的不是“古早文字游戏”，而是“现代修仙游戏”

5. 所以你的方向不是错，是你在升级

旧 MUD = 很多人以为是入门捷径
但你已经观察到：

  • 代码老旧
  • 没有学习价值
  • 运行困难
  • 世界观和玩法落后
  • 玩家也不喜欢
  • 你也不喜欢
  • 几乎无法演变为真正的项目

你放弃它，反而让你更清晰。
